<rule id="set-tested-field">At Complete (step 7), set the Asana `tested` multi-select to the testing method(s) this run ACTUALLY performed, matching the run-report Testing section: `~/.config/agent-watcher/set-tested.sh <gid> <Option ...>`. Options (pass every one that genuinely ran, space-separated, quote multi-word): `"iOS Sim"` (drove the change in-app on the iOS sim to terminal success — the DEFAULT sim platform), `"Android Sim"` (Android EMULATOR exercise: gradle `:app:assembleDebug` for a build-only fix, or an AVD/maestro drive — only for Android-called-out tasks), `"Android Device"` (a PHYSICAL Android device drive, e.g. the S9 — never recorded as Android Sim; added 2026-08-06), `Unit Tests` (jest/mocha/`npm test` ran), `CouchDB` (a CouchDB-backed test ran — sync/server repos), `Untested` (NO test method applied — only static tsc/lint, or nothing; mutually exclusive, never combine with a real method). The field documents what THIS run actually performed — do NOT carry forward a prior run's credit, and do NOT count CI's own jest run as this run's `Unit Tests` (only credit `Unit Tests` when the run itself executed the suite). On a followup/re-run, recompute the field from this run's evidence, replacing the prior value (a stale credit is an A22 finding). This is a structured mirror of the Testing section; the eval's testing-depth and tested-field dimensions audit its honesty. Skip silently if no task GID (ad-hoc run).</rule>
</rules>

<step id="4" name="Local verification — orchestration only">
**`--yolo` (orchestration) only — SKIP this step entirely on manual runs.** A human running `/one-shot` by hand verifies as they see fit; do NOT run `/build-and-test` for them. In `--yolo`: run `/build-and-test` on the implemented branch BEFORE opening the PR, so the PR opens already-verified. "Verified" means `/build-and-test` actually drove the **real end-to-end user action to its terminal success in the running app on the sim** per `test-on-sim-by-default` + `test-drives-the-real-action` — NOT `tsc`/build passing, NOT a precursor. A swap-plugin change is verified only when a swap actually EXECUTES in-app (the success scene), never at the quote; do every prerequisite (link the dep into core/gui, build, fund/switch accounts) to get there. Do NOT declare the Testing phase done by static reasoning, by "it builds", or by stopping short at a quote/partial step. Set agent_status=Testing at the start of this step (on-sim/local verification is its own phase per `agent-status-on-pending-task`, between Developing and the PR). No PR exists yet, so fixes amend the local commit (no force-push). If it fails, amend HEAD with the fix (`git commit --amend --no-edit`) and re-run; repeat up to 2 times. If still failing after 2 attempts, take the blocked completion (`Complete --blocked yes` with the reason, per `yolo-true-blockers`) — do NOT open a PR on red local verification.
</step>
